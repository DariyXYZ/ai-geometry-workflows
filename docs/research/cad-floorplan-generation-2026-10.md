# Генерация CAD-планировок: офисы сначала, жильё дополнительно

Проверено: 2026-10-06. Цель: быстро получать **редактируемые варианты планировок** бизнес-центров в Rhino/Grasshopper и передавать выбранный вариант в Revit. Это обзор исходников и практический маршрут разработки, а не проверка качества алгоритмов на наших проектах. Состояние лицензий сверено по репозиториям на дату обзора; лицензии зависимостей и данных проверять отдельно перед внедрением.

## Короткий вывод

1. **Самый доступный старт:** Rhino/Grasshopper + правила зонирования/расстановки + проверка ограничений. В Revit уже есть [образец Workspace Layout для Generative Design](https://help.autodesk.com/cloudhelp/2022/ENU/Revit-Model/files/GUID-FE9FB46D-08D9-4668-94C8-32EAF96B0E7C.htm), а Autodesk публикует [учебные Dynamo-графы и Revit-данные](https://www.autodesk.com/support/technical/article/caas/tsarticles/ts/5Ppv9Cj9Eo26SmEczdx2ox.html). Это быстрый пилот для **расстановки столов в готовом помещении**, не генератор целого офисного этажа.
2. **Лучший открытый донор офисной логики:** [hypar-io/HyparSpace](https://github.com/hypar-io/HyparSpace) (MIT, C#): space planning, circulation, open/private office, meeting, reception, pantry, furniture и анализ расстояний. Код работает вокруг Hypar Elements/форматов; перенос в Rhino/Revit потребует адаптера. Два актуальных модуля [SpacePlanning](https://github.com/hypar-io/Function-SpacePlanning) и [Circulation](https://github.com/hypar-io/function-Circulation) подключены как **отдельные git submodules без найденной лицензии** — их исходники нельзя автоматически считать покрытыми MIT лицензией родителя.
3. **Надёжное ядро для наших ТЗ:** [Google OR-Tools CP-SAT](https://github.com/google/or-tools) (Apache-2.0) для размещения помещений/модулей с жёсткими ограничениями, плюс RhinoCommon для кривых и геометрической проверки. CP-SAT работает с целыми числами, поэтому размеры можно дискретизировать, например до сетки 100 мм; это инженерное решение, а не готовый архитектурный генератор. [Документация CP-SAT](https://developers.google.com/optimization/cp/cp_solver/).
4. **Нейросети подключать позже:** открытые модели планов преимущественно обучены на **жилье**, требуют собственного набора офисных данных и отдельной проверки геометрии/норм. Красивая картинка сама по себе не является CAD/BIM-планом.

## Карта методов и AI-инструментов

| Метод | Когда полезен | Что отдаёт в CAD |
| --- | --- | --- |
| Правила/шаблоны + сетка модулей | Быстрый офисный test fit с фиксированным ядром | Предсказуемые зоны, коридоры и расстановка; самый простой для дебага |
| CP-SAT / целочисленная оптимизация | Несовместимые варианты, площади, соседства, неизменяемые зоны | Валидные раскладки с явными причинами отказа; качество задаётся нашей функцией оценки |
| Генетический поиск / многокритериальная сортировка | После генерации допустимых вариантов, когда нужен выбор по нескольким метрикам | Разнообразный Pareto-набор; каждое решение всё равно валидировать отдельно |
| RL (пример `layout_optim`) | Когда есть много собственных кейсов и понятная награда | Быстрое предложение расстановки, но возможны нарушения жёстких условий |
| GNN/diffusion (`Graph2Plan`, `GSDiff`) | Исследование после накопления офисного датасета | Черновые полигональные схемы; обязательна геометрическая очистка и валидация |
| LLM/агент + [RhinoMCP](https://github.com/mcneel/RhinoMCP) | Преобразовать текстовое ТЗ в структурированный JSON, запускать проверяемый генератор, объяснять варианты | Оркестрация и команды Rhino; LLM не должен единолично рассчитывать геометрию/нормы |

Для быстрой автоматизации внутри нашего стека есть локальные навыки `grasshopper-script-nodes` (C#/Python узлы), `grasshopper-plugin-development` (компилируемый `.gha`) и текущий `ai-geometry-workflows` с правилами RhinoMCP. Эти навыки ускоряют написание адаптера и проверок, но не содержат готового планировщика офисных этажей.

## Что делать в Rhino/Revit: минимальная архитектура

```text
Rhino/Revit: контур этажа, колонны, ядро, шахты, входы, фасад, неизменяемые зоны
  -> нормализованный JSON в метрах: FloorPlate + Obstacles + Anchors + Program + Rules
  -> генератор вариантов:
       1. фиксируем ядро/обязательные связи и строим связный коридорный граф;
       2. делим доступную площадь на зоны (периметр/центр, модули/ячейки);
       3. CP-SAT/эвристика размещает переговорные, кабинеты, open space, сервис;
       4. расставляем столы/мебель внутри валидных зон;
  -> независимый валидатор: геометрия, площади, двери, связность, выходы, метрики
  -> N ранжированных вариантов + причины отказа каждого невалидного решения
  -> GH/Rhino слои и атрибуты -> согласованный вариант -> Rhino.Inside.Revit
```

**Входы первого пилота:** один типовой офисный этаж, контур и единицы, колонны/ядро/шахты, входы/выходы, список помещений с площадями и приоритетами соседства, целевое число рабочих мест, библиотека мебельных модулей, локальный набор правил. Неизменяемые исходные элементы должны сохраняться как source geometry.

**Жёсткие проверки:** внутри контура; без наложений и пересечений фиксированных объектов; связный путь от каждого помещения до принятого выхода; двери на доступных границах; площади/габариты в заданном диапазоне; результат редактируем и привязан к правильным уровням/единицам. Эвакуационные, пожарные и доступные размеры задавать конфигурацией проекта по проверенным нормам региона, а не константами из случайных GitHub-примеров.

**Ранжирование после валидности:** число мест, эффективность полезной площади, длина маршрутов, доля помещений у фасада, длина перегородок, вариативность кабинетов/переговорных, близость нужных команд. Показать архитектору несколько непохожих решений и их метрики; численный score не заменяет архитектурный просмотр.

**Путь прототипа:** (1) повторить на выбранном этаже Workspace Layout в Revit как baseline; (2) импортировать тот же этаж в Rhino/GH, реализовать JSON и правила/CP-SAT для офисных зон; (3) заимствовать переносимые фрагменты HyparSpace с проверкой лицензий и адаптером; (4) выбранный вариант создавать в Revit через Rhino.Inside.Revit; (5) только после оценки на собственных кейсах собирать очищенный офисный датасет и проверять ML/RL против solver baseline.

## Рыночные ориентиры и данные

- [Hypar Space](https://docs.hypar.io/d6f714da482c4eeca02e9e40aa479596): коммерческий workflow для офисного test fit с входом из Revit, DXF или изображения; открытые части перечислены выше, сам сервис и вся цепочка не обязательно open source.
- [Finch](https://www.finch3d.com/product): ориентир по UX вариантов/Plan Library; [экспорт в Revit/Rhino/GH](https://docs.finch3d.com/docs/projects-and-variants/export). Закрытый продукт, не донор алгоритма.
- [TestFit](https://www.testfit.io/news/testfit-launches-groundbreaking-generative-design-for-better-building-optimization): ориентир ранней генерации и оценки девелоперских вариантов; закрытый продукт.
- [FloorPlanCAD](https://floorplancad.github.io/): планы жилых и коммерческих зданий для распознавания CAD-символов, не готовый датасет офисного space planning. Лицензия и доступность загрузки требуют отдельной проверки; не включать в обучение по умолчанию.

## Решение для следующего спринта

Сделать **один офисный этаж как эталон** и сравнить ручной план, Autodesk Workspace Layout (только столы) и собственный GH/CP-SAT прототип. Успех: каждый вариант проходит геометрические и программные проверки, имеет объяснимые метрики, сохраняет исходное ядро/колонны, редактируется в Rhino и выбранный вариант переносится в Revit без потери назначений помещений. Нейросеть оценивать после этого baseline и только на данных с подходящими правами.
